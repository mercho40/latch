# Using Latch

Behaviour of the macOS app as it ships today. The iPhone and iPad app is described in [Latch for iPhone and iPad](ios.md).

## Sessions and agents

Choose a workspace folder and select fx, Codex, Claude Code, OpenCode, or a custom ACP agent. Opening a session connects its locally discovered default harness; selecting another harness connects it immediately. Model and effort options load before the first prompt. Send only sends to an already-connected session and never starts or retries a connection. Stop cancels setup or the active response without losing an unsent draft. Reselect the harness in the toolbar to rescan and retry. Settings → Agents (⌘,) lists every agent with one line about its state and a switch for whether the agent menu offers it, and holds the custom command. Reselecting an already-connected harness rescans but keeps the live session, its history, and any unsent draft. You can switch harnesses while idle or connecting. New sessions remain available from the toolbar or ⌘N. With no session selected, the window asks what to build and lists up to five recent workspaces, each one click from a new session there; New Session… chooses any other folder. Close one with ⌘⌫, the sidebar's context menu, or File → Close Session: its agent stops and it leaves the saved library, and ⌘Z reopens it in the same place with its title, transcript, unsent draft, and agent context. The window reopens at the size and position it was left at.

Built-in setup is automatic: Latch reuses an installed integration or silently starts the pinned fallback on first connection. There is no installation dialog or adapter confirmation, and built-in launch commands are not shown; where an installed agent was found is in its row's tooltip in Settings → Agents. For Codex, sign in with `codex login`; for Claude Code, set up your Claude login and Node.js 22+. Claude Code's adapter runs the `claude` you installed when Latch finds one, so sessions get the models and fixes of the release you use in the terminal; without one, it runs the older Claude Code it bundles. Set `CLAUDE_CODE_EXECUTABLE` to choose another. First-time setup may need Node.js with npm and internet access. fx and OpenCode use their installed commands and existing provider authentication. Missing prerequisites and startup failures appear in a banner above the conversation: the agent's own words on one line in monospace, then one line of advice, then Retry and Agent Settings…. After installing a prerequisite, press Retry or select the agent again to rescan.

Custom ACP Agent runs any ACP server. Set its command in Settings → Agents by typing it or choosing an executable; the command is saved and used by every session that selects the custom agent. Commands support quotes and backslash escaping, not shell expansion or pipelines. On disconnect the transport closes stdin and sends SIGTERM to the agent's process group, then force-kills the group if the agent has not exited within five seconds. Disconnecting waits only for the agent itself: a tool child it started that is still running at the five-second mark is killed then, in the background, even when the agent exited sooner.

## Remote sessions

A session can run its agent on a machine running `latch-server`; [Running latch-server](server.md) covers setting one up. Settings → Servers lists your servers. Add Server… takes the string `latch-server pair` prints, or a name, host, port and token; Test Connection reports the server's host name, system and version, or why it could not connect. Edit…, or double-clicking a server, changes its name, address or token in place: a pasted pairing string replaces the host, port and token together, a token field left empty keeps the current one, and the server's sessions stay on it. Each server has an Allow unencrypted network switch, off by default, and its own custom agent command, which runs on the server. Removing a server forgets its token; its sessions stay in the sidebar under "Removed server" and cannot connect again, even if the server is added back, since that makes a new entry. Session → New Remote Session… (⌥⌘N) asks for a server, a folder on it and an agent; the folder is typed, starting at the server's home folder, because Latch cannot browse the server. In the sidebar a remote session's group names its server as well as its folder. A remote session sends images to an agent that accepts them, but not files or folders, which stay on the Mac. Reveal in Finder and Open in Terminal are unavailable for it, and Copy Path copies the server's path. Servers and their tokens are saved in `servers.json`, readable only by you, beside `sessions.json`. A library holding a remote session is saved as version 2, which Latch 0.1.0 refuses to open, and one holding the agent's thinking as version 3, which Latch 0.2.0 refuses to open.

A remote session's agent runs on the server whatever the Mac does. While the server is out of reach, the session says it is reconnecting and catches up when it answers again; the turn in progress and any permission sheet wait for it. A server that has not answered at all within fifteen seconds of a session connecting fails the connection, with Retry and Server Settings…, which opens Settings on that session's server. Quitting Latch leaves remote agents running: each session remembers its agent, and the next launch attaches to it in the background, catches up on what it did, raises any permission request still waiting, and announces the turn it left running if that finished meanwhile. Closing a remote session, or Session → Disconnect, stops its agent on the server, and ⌘Z after a close starts the agent again and resumes its saved session. Removing a server stops none of its agents, so close its sessions first: after Latch relaunches, a session on a removed server cannot reach its agent, and closing it leaves the agent running until the server's idle timeout or something on the server stops it. Changing a server in Settings keeps its sessions: those following an agent reach it the new way at once, a prompt still waiting for the link included, and those that could not reach it attach again. So after rotating a server's token, paste the new pairing string into Edit…: the sessions the server refused attach again to agents that never stopped. When another client stops the agent, or the server shuts down while the session is connected, the session says the agent was stopped on the server; one that finds its agent gone, after the server restarted or its idle timeout ended the agent, says it is no longer running there. Either way, Retry starts the agent again and resumes its saved session. A session that finds its agent gone when Latch opens does this by itself, and says so in the transcript if a turn was running when Latch quit, since its output from while Latch was closed is lost; one whose agent another client stopped meanwhile says it was stopped on the server, and waits for Retry.

## Sidebar

Sessions are grouped by workspace, each row a title over the agent's name. A session at rest shows how long ago it was last active on the right of its title — "now", "5m", "3h", "2d", "3w", then a date — counted from the last prompt sent or turn finished. That slot gives way to anything that needs you: a spinner while connecting or working, with the second line counting the turn ("Working · 1m 12s"); an orange mark while a permission decision waits; a red one for a failure; and an accent dot, with the title in bold, for a reply that finished while another session was on screen. Under the pointer the slot becomes a close button. Times from before this was kept are not shown until the session is next used.

## Attention

A permission request opens a sheet headed by what the agent says it wants, with its reason, and below it the plan when the agent asks to go ahead with one, or else the tool call's details; each choice keeps Latch's own label, and what the agent says the choice means sits beside it. When the agent asks a question, such as Claude Code's AskUserQuestion, a sheet shows it with its options and their descriptions, a box for an answer of your own, and Submit, Skip, which tells the agent you passed, and Cancel Request, which refuses it.

Sessions keep running while Latch is behind another app, so attention comes to you. A permission request, a question, or a finished turn, in a session you are not looking at posts a notification, including one from a server that came while Latch was closed, posted once Latch opens and catches up; Allow Once and Reject Once sit on the notification itself, while clicking its body only brings the session forward, because approving something unread is not a decision. Notification text names the workspace folder, and for a remote session its server, and nothing else — no prompt text, tool name, or argument. A turn that ended because its agent was stopped on the server says so rather than that it finished. The Dock icon badges how many sessions are waiting for a decision and bounces once when one arrives in the background. A menu bar extra lists every session with its state and leads back to any of them; hide it from its own menu, and View → Show in Menu Bar brings it back. While it is showing, closing the window no longer quits Latch. The SwiftPM preview has no bundle identifier and therefore posts no notifications; the Dock badge and the menu bar extra still work.

## Menus, drag and drop

The Session menu carries the session commands with keyboard equivalents: Attach Files… (⇧⌘A), Stop (⌘.), Fork Session (⌘⇧N), Resume Conversation…, Disconnect, Rename…, Reveal Workspace in Finder, Open Workspace in Terminal, and Previous/Next Session (⌥⌘↑ and ⌥⌘↓), each disabled when it cannot run. A folder dropped on the sidebar or on the empty detail pane opens a session in it, as does one dropped on the Dock icon or opened from the Finder, and File → Open Recent lists the workspaces you have opened. Right-clicking a session offers rename, fork, reveal, open in Terminal, copy path, and close; right-clicking a workspace offers the workspace actions alone. Renaming is inline in the row, and Escape keeps the previous name. With an agent that forks its conversations, as Claude Code does, Fork Session opens a session beside this one with a copy of the conversation, which goes on separately from there; otherwise it opens an empty one on the same agent. In a new session, Resume Conversation… lists the agent's own saved conversations in the folder, including ones started in its command line, and the one you choose goes on in that session with its history and title.

## Find, App Nap, and saving

⌘F opens a find bar over the conversation. It matches the text that is actually on screen, case- and diacritic-insensitively, in reading order; ⌘G and ⇧⌘G step through matches and wrap at either end, showing each in a native find indicator. Collapsed tool rows, folded thinking and the rows under a folded subagent are not searched because there is nothing on screen to reveal, and Escape or Done closes the bar. A prompt in flight is registered as user-initiated activity so App Nap cannot throttle streaming while Latch is in the background; the Mac may still sleep on its own schedule. Saving sessions holds off sudden termination for the length of the write.

## Conversation and composer

The quiet native chat uses one content column shared by the transcript and composer, selectable replies, and compact tool updates that sit together as a group. Code blocks are padded panels and quotes carry a bar; a failed or running tool says so in colour as well as in words. The window resizes to the full screen and the conversation fills the pane, replies included, so wide tool output, diffs and tables get the room; no content constraint may become the window's maximum width. An edit's details show what changed as unified hunks with three lines around each change, and a reply cut short at the agent's length or step limit, or that it refused, says so where it stops. Long tool titles are shortened in the middle, keeping their status, with the whole line in the tooltip; a symbol before each says what kind of call it is, such as a read, an edit, a search or a command. What the agent thought on the way shows as a folded Thinking row headed by its first line. A subagent's call is one folded row that says how many steps it has taken and, while it works, the latest; opening it shows the subagent's own calls, words and thinking indented under it, with a guide line, wherever the main agent's messages fell between them. While the agent has a plan, a panel over the composer says how many of its steps are done and which is in hand, and opens into the whole checklist; it gives way to the command menu. In dark mode the conversation sits on a page darker than the sidebar, running up under the toolbar. Process diagnostics are not included in the conversation. A session with no messages opens on a heading naming its workspace. The composer shares that column and offers native model, effort, and permission-mode pop-ups only where supported, then the agent's own other options under their names, such as Claude Code's Fast mode, each as wide as the title it shows, with each option's description as a second line in its menu: on macOS 26 and later they are the same Liquid Glass capsule as the agent control in the toolbar, and borderless before it. Controls have 36-point hit targets, wrapping onto another row in narrow windows rather than being squeezed. A message sent while the agent works goes into its turn when the agent steers, as Claude Code does: the agent takes it at its next step, and it shows in the conversation where it went in. With an agent that does not, or once the turn has ended, it waits over the composer, marked with a clock, and goes when the turn ends, in order; Edit puts one back in the composer and × takes it out. Stop gives everything still waiting back to the composer. Before the buttons, when there is room, a note says how full the agent's context is, such as "25% context", amber from 80%; its tooltip has the tokens and what the conversation has cost so far. A session named by its first prompt takes the title the agent gives the conversation, as Claude Code does after a turn, but a name you gave it stays. Return or ⌘ Return sends; Shift Return inserts a newline; Stop cancels the active response. Typing `/` at the start of an empty draft lists the commands the agent advertises, filtered as you type: the arrows move, Return or Tab chooses, Escape closes, and a chosen command shows what it expects next in grey. Files, folders and images can be pasted, dropped on the composer, or chosen with the paperclip or Session → Attach Files…; up to ten wait above the draft with a remove button each, and a message can be attachments alone. Images are scaled to at most 1568 pixels on the long edge and sent as images to an agent that accepts them, otherwise as a link to the file; files and folders go as links the agent opens itself. A sent message lists its attachments by name; image data is not saved, and attachments waiting in the composer are not kept with the draft. Each composer keeps its own undo stack, so ⌘Z there edits that draft and never reaches the session list. Spelling is checked, but nothing is rewritten: autocorrect, text replacement, and quote and dash substitution stay off for paths, flags, and identifiers. The header carries only the harness pop-up and status text. Native Markdown supports a subset of headings, emphasis, lists, quotes, links, and fenced code; it is not a browser or full CommonMark renderer. HTML and remote resources are not rendered or loaded. Per-message Copy preserves the original Markdown, while normal text selection copies the rendered text. Edit → Copy Conversation copies the retained messages and tool activity. Streaming follows the bottom unless you scroll up, with a round Jump to Latest arrow to return. History is bounded to 400 messages / 200,000 text characters and is saved with the session library in `~/Library/Application Support/Latch/sessions.json`. System colors and fonts follow macOS appearance; there is no web view or JavaScript UI.
